## Achados reproduzíveis

### Alta — a instância 4000 configura retorno para o domínio de produção

A UI local usa `NEXT_PUBLIC_API_URL=http://localhost:4000/api`. O processo 4000 não tem override de `FRONTEND_URL`; `backend/.env` define `www.inove-esg.com.br`. `buildBackUrls()` usa `env.frontendUrl` para retorno de sucesso/falha/pendência. Assim, a primeira preferência criada pela UI local fornece retorno de produção. **Reprodução:** abrir Plano 2.2 pela UI local autenticada, clicar em Comprar agora e observar a preferência gerada pelo backend 4000. Não usar esse link nem concluir compra.

### Alta — a instância 4001 envia notificações a localhost

Na tentativa isolada roteada ao backend de teste 4001, o GET read-only da preferência retornou `notification_url` com host `localhost`; o provedor não consegue entregar webhook a esse endereço. O túnel ngrok de backend configurado no arquivo `.env` retorna 404 em `/api/health`. A preferência de teste tem `back_urls` apontando ao túnel f797, mas isso não corrige a notificação inacessível.

### Alta, análise estática — valor de sandbox de R$ 0,01 não é condicionado ao modo de teste nem validado no webhook

O GET read-only da preferência confirmou unit price de R$ 0,01 enquanto o pedido local do Plano 2.2 totaliza R$ 38.000,00. O código define o valor externo em `backend/src/lib/mercadopago.ts:46`. O webhook consulta o pagamento e, ao receber `approved`, chama `confirmPayment` sem comparar o valor/moeda externa ao pedido (`backend/src/modules/webhooks/services/mercadopagoWebhookService.ts:78-88`). O caminho de concessão por valor divergente não foi executado; isso é uma lacuna de verificação com risco caso configuração live seja usada.

### Média — erro 403 no checkout sandbox

Com URL sandbox confirmada, a página do provedor mostra erro genérico e não oferece formulário de comprador. A rodada não autenticou o comprador nem tentou cartão. Reproduzido duas vezes, com preferências distintas/rotas de backend diferentes; o erro permaneceu.

## Melhorias priorizadas

1. Configurar a UI local para usar consistentemente o backend 4001 de teste, cujo `FRONTEND_URL` é o túnel de teste; manter validação que rejeita retorno para domínio de produção em rodadas locais.
2. Configurar `BACKEND_URL` para um túnel de backend realmente ativo e validar endpoint antes de criar preferência. Confirmar que a notificação pública alcança o webhook local.
3. Tornar o preço R$ 0,01 exclusivo de sandbox explícito; em live usar o valor contratado. No webhook, conferir moeda, montante, referência e pedido antes de marcar PAID ou conceder acesso.
4. Diagnosticar resposta 403 do checkout sandbox e repetir com comprador de teste apenas após callbacks/notificações estarem corretos.
