# QA exploratório — InoveESG — 20261104-qa-checkout-01

- **Período:** 04/11/2026, aproximadamente 14:01–14:31 BRT.
- **Ambiente:** frontend e backend locais; Supabase remoto confirmado como ambiente de teste.
- **Navegador:** Playwright 1.64.1, Chromium headless.
- **Conta:** cadastro e login com conta sintética própria (`qa.c***@example.invalid`).
- **Resultado geral:** checkout gerado com HTTP 201, mas o destino sandbox do Mercado Pago respondeu HTTP 403. Nenhum pagamento foi submetido.

## Percurso

1. Na interface, selecionei o card **Diagnóstico Autodeclarável**. O catálogo respondeu HTTP 200 e exibiu **R$ 250,00**.
2. O primeiro botão **Comprar** abriu o detalhe do serviço. No detalhe **Pré-Diagnóstico ESG Autodeclarável**, o preço permaneceu em R$ 250,00.
3. Cliquei **Comprar Agora** no detalhe. A aplicação enviou `POST /api/checkout/preference` com `productCode: PRE_DIAGNOSTIC` e `quantity: 1`. A resposta foi **HTTP 201 em 3,68 s**.
4. O navegador chegou a `https://sandbox.mercadopago.com.br/checkout/v1/redirect` (parâmetros da URL omitidos). O GET do provedor levou **184 ms** e respondeu **HTTP 403** com página HTML de erro em espanhol.

A preferência foi criada a partir do serviço selecionado na interface. A compra não foi concluída e nenhum dado de pagamento foi informado. O fluxo também criou um pedido pendente de teste no backend.

## Investigação do HTTP 400

O HTTP 400 não se reproduziu na compra válida: `POST /api/checkout/preference` retornou 201. A resposta problemática observada foi o **403 do host sandbox**, já após a aplicação retornar do endpoint local.

A inspeção de `backend/src/modules/checkout/controllers/checkoutController.ts` mostra que a validação Zod e qualquer exceção capturada pelo serviço são convertidas em HTTP 400. Portanto, se o 400 aparecer novamente, a mensagem sanitizada da resposta e o erro correlacionado do backend serão necessários para distinguir entrada inválida de falha interna/provedor. Não enviei requisição para produto inválido ou sem seleção de serviço.

## Autenticação

- Cadastro sintético pela interface: **HTTP 201**, 6,65 s.
- Login pela interface: **HTTP 200**, aproximadamente 1,5 s.
- Perfil, contexto de acesso e preços carregaram com HTTP 200 no login em contexto novo. A tela mostrou brevemente “Carregando seu perfil...” logo após o cadastro; o login posterior carregou a página de serviços.

## Evidências

As chamadas foram sanitizadas: sem senha, cookies, tokens, identificadores internos, CPF/CNPJ ou query string do checkout. O evento de resposta do POST ficou sem o JSON legível porque a navegação para o provedor ocorreu junto da leitura da resposta; o status 201, tempo, código de produto, quantidade e destino sandbox foram capturados.
