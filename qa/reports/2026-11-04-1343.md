## Mercado Pago: documentação e verificação

A documentação oficial atual distingue credenciais de teste e produção e orienta selecionar o ambiente **Teste** no painel. Para Checkout Pro, o Access Token de teste pode começar com `APP_USR`; esse prefixo isolado não distingue credenciais de teste de produção. A mesma documentação recomenda usar a conta compradora de teste para realizar compra. [Credenciais de teste](https://www.mercadopago.com.br/developers/pt/docs/checkout-pro-orders/resources/credentials) · [Contas de teste do Checkout Pro](https://www.mercadopago.com.br/developers/pt/docs/checkout-pro-preferences/test-accounts) · [Compra de teste no Checkout Pro](https://www.mercadopago.com.br/developers/pt/docs/checkout-pro-preferences/integration-test/test-purchases)

A consulta autenticada `GET /users/me` com a credencial configurada retornou HTTP 200 e marcou o usuário com tag `test_user` e padrão de nickname de usuário de teste. A preferência retornou `init_point` e `sandbox_init_point`; somente o segundo foi aberto. A API documenta os dois destinos. **Inferência de segurança:** URL sandbox prova o destino visitado, mas, sozinha, não prova que o vendedor, comprador e credenciais usados no fluxo são de teste; a identidade de vendedor foi confirmada pela API, mas não havia comprador de teste verificado. Por isso nenhum cartão foi submetido. [Resposta da API de preferências](https://www.mercadopago.com.br/developers/pt/reference/online-payments/checkout-pro-preferences/create-preference/post)

A documentação oficial lista cartões sintéticos e resultados simulados por nome do titular (`APRO` aprovado, `OTHE` recusado, `CONT` pendente, entre outros). Nenhum cartão foi usado nesta rodada. [Cartões oficiais de teste](https://www.mercadopago.com.br/developers/pt/docs/checkout-api-orders/integration-test/cards)

## Achados

1. **Cadastro bloqueado pelo schema do ambiente (alta).** A tabela aditiva `email_outbox` exigida pelo cadastro não existe no Supabase de teste. Evidência: [registro sanitizado](../artifacts/20261104-r4/registration-blocker.txt). A migration existente não foi aplicada.
2. **Webhook não valida assinatura (alta).** Um `x-signature` inválido não é verificado antes de aceitar eventos ignorados. Corrigir e adicionar casos localmente antes de depender do endpoint público.
3. **Checkout sandbox retorna 403 (média).** A preferência e o domínio sandbox foram confirmados, mas a tela de pagamento não carregou. Evidência: [screenshot](../artifacts/20261104-r4/checkout-sandbox.png) e [resumo sanitizado](../artifacts/20261104-r4/mp-preference-summary.json).
